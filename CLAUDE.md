## 0. TL;DR

A single‑file web app + a local full‑wave simulation bridge that evaluates **lightweight, thin‑film‑coated materials (flagship: MXene‑coated basswood) as replacements for heavy solid‑metal satellite waveguides and horn antennas.** It predicts a material's RF loss, weight and launch‑to‑orbit cost instantly (analytical engine), and validates the chosen design with a real 3‑D FDTD solve (openEMS). Current version: **v3.8**.

Author: **Huzaifa Taha Rangwala** — UC Berkeley (Math + CS); Visiting Researcher / SWE, Khalifa University, Abu Dhabi. Contact: huzaifataha54@berkeley.edu. Page header reads `KHALIFA UNIVERSITY · جامعة خليفة`.

Development happens on the **Mac** (Homebrew openEMS); a Windows PC runs the always-on bridge for a
remote tester. **Sync is via git** (a private repo), not file-copy tools — file sync can't merge and
silently loses one side's edits. Commit on the Mac → push → `git pull` on Windows. **Full workflow,

machine-local installs are git-ignored (see `.gitignore`); the Windows runtime (`C:\opt\openEMS` incl.
the Octave-11-rebuilt `h5readatt_octave.oct`, `C:\opt\mesa`, env vars, the venv, Tailscale) lives
**outside the repo** and is set up once per machine — see `openEMS/WINDOWS_SETUP.md`.

**Windows-portable, macOS-unchanged code (do NOT strip it):** the openEMS Python renderers
(`render_field.py`, `render_field_freq.py`, `render_rcs.py`, `cad/render_horn.py`, `cad/view_stl.py`)
contain blocks guarded by `if os.name == "nt":` — a **Mesa software-OpenGL preload** (so off-screen
rendering works in a headless/RDP-disconnected Windows session, where system GL has no pixel format and

macOS `add_volume` path (`OPENEMS_FIELD_RENDER=volume|surface`, default surface on Windows only). These
are **no-ops on macOS/Linux** — the Mac render path is byte-for-byte unchanged. When editing these files
for a feature, keep the Windows blocks intact.

## 2. What it is (research context)

Solid copper/aluminum waveguides and horns are electrically excellent but heavy, and every kg to orbit costs thousands of dollars. The research question: can a **lightweight structure with a thin conductive coating** (flagship MXene = Ti₃C₂Tₓ on basswood) do the same job at a fraction of the mass? The tool quantifies the RF‑performance ↔ weight ↔ cost trade for any material, across the **X (8–12 GHz, WR‑90), Ku (12–18 GHz, WR‑62), K (18–27 GHz, WR‑42)** satellite bands.

## 3. Architecture — two engines

**Engine 1 — Analytical (in‑browser, instant).** Closed‑form microwave physics in vanilla JS inside `waveguide_simulator.html`. Rectangular‑waveguide TE10 conductor attenuation, skin‑depth + finite‑coating corrected, complex ε/μ, a multilayer transfer‑matrix stack, far‑field/horn equations, Monte‑Carlo UQ. Recomputes on every control change. Validated against 13 textbook anchors.

**Engine 2 — openEMS full‑wave FDTD (local).** A Python **Flask bridge** (`openEMS/openems_server.py`, port **8731**) serves the HTML and, on "Run" requests, launches **GNU Octave** scripts that drive **openEMS** (free FDTD Maxwell solver), post‑processes the field dumps with **Python/NumPy/PyVista**, and streams charts/images/3‑D field data back to the page. The page must be opened at `http://localhost:8731` for the Run buttons to work (same‑origin fetches to `/run`, `/run_horn`).

Everywhere the two overlap, the **analytical curve is dashed** and the **openEMS curve is solid**, so agreement is visible.

## 4. Run & verify

**Analytical only (no server):** open `waveguide_simulator.html` in a browser. Everything works except the "Run on openEMS" buttons.

**Full‑wave (the bridge):**
```
pip install flask pyvista imageio imageio-ffmpeg numpy   # (use --break-system-packages if needed)
# install openEMS + GNU Octave (see openEMS/SETUP.md)
python "openEMS/openems_server.py"        # prints http://localhost:8731
# open http://localhost:8731 in a browser, then use the Run buttons
```
A horn or waveguide solve takes ~1–3 minutes. See `openEMS/SETUP.md` and `openEMS/RESUME_TOMORROW.md` for environment details.

**Analytical engine (core functions, near the top of the main `<script>`):**

## 8. Gotchas / landmines (learned the hard way)

- **`var()` does NOT resolve inside SVG presentation attributes** (`fill="var(--x)"`, `stroke="var(--x)"`). Use literal hex or `style="fill:var(--x)"`. (Rendered the hero art black once.)
- **A raw `<` in MathJax equations** is parsed as an HTML tag and can eat `</div>` and blank whole tabs. Use `\lt` (and be careful with `|S11| < -10` etc.).
- **Global Chart.js plugins that throw blank ALL charts.** Keep chart customizations per‑chart and defensive.
- **Chart.js created inside a `display:none` container inits at 0×0 and never repaints when shown** (the canvas has no container width at construction). Symptom: a blank/short chart panel while the headline + any raw‑`<canvas>` heatmap render fine. **Always reveal the panel (`fig.style.display=''`) BEFORE `new Chart(...)`, then call `chart.resize()` (synchronous).** This bit the RL tab's RL‑vs‑freq + RCS charts and the Inverse‑RAM Pareto/refl charts (all fixed: draw functions now show‑then‑create, and `repaintRL()` resizes). NB: the in‑app automation Browser pane has a **0‑width viewport** (full‑width panels collapse; only CSS‑grid `minmax(300px)` tracks get sized), so you cannot confirm full‑width Chart sizing there — force a width on the panel and call `resize()` to verify the chart paints, or check in a real browser.
- **Down‑range profile (RCS `range` sim): reference the IFFT to the dominant scatterer, not absolute range 0, and floor non‑finite dB.** openEMS NF2FF far‑fields carry the reference‑sphere phase `e^{-jkR}`, a large linear‑in‑f term that displaces the whole down‑range profile by the (arbitrary) far‑field distance — often **hundreds of mm**, outside the plotted ±clip window. `drawRange` normalized the small window to the **global** peak (which sat outside it), pushing every plotted point to ≈−48 dB, **below the chart's −40 dB y‑floor → axes drew but no curve** (the exact symptom the owner reported). Fix: track the peak bin `npk`, reference ranges to it (`d=n−npk` wrapped to ±M/2), normalize to that peak (dominant scatterer = 0 mm / 0 dB — standard ISAR practice), and floor non‑finite dB (`20·log10(0)=−∞`, and `(−Infinity).toFixed()` → the string `"-Infinity"` → `+…` = NaN, which Chart.js silently drops). Any IFFT / peak‑normalized chart with a **fixed** y‑axis needs both guards. Validated: dominant return at 0 dB/0 mm, 88 visible points (was 0).
- **Monostatic PO plate sinc uses the FULL dimension: `u = k·w·sinθ`** (not `k·(w/2)`). Backscatter is round‑trip, so the aperture phase slope is `2k sinθ` over ±w/2 → argument `k·w·sinθ` (Knott `sin(ka·sinθ)/(ka·sinθ)`, a = full dim; first null at `sinθ=λ/2w`). A half‑argument bug put every plate null/sidelobe at 2× the correct angle (boresight `4πA²/λ²` is unaffected — the error hides at θ=0). Fixed in `rcsPOPlate` and the RL‑tab `poPlate`; the bistatic variants are a separate (one‑way) geometry — leave them.
- **The `/run_rcs` electrical‑size guard MUST mirror `rcs_run.m`'s per‑shape geometry** (sphere/import→size1; cylinder/dihedral→max(size1,size3/2); plate→max(size1,size2)/2). A generic `max(size1,size2/2,size3/2)` over‑rejected: it never halved size1, so the flagship 180×180 mm plate (true half‑extent 90 mm) was judged 180 mm > 5λ and 400'd, silently killing the RL→openEMS "Send to full‑wave" validation.
- **The bridge writes to fixed paths** `/tmp/horn_sim`, `/tmp/wg_sim` and shared result dirs → **concurrent runs collide**. Single‑user at a time unless you add a lock/per‑session dirs.
- **`app.run` host/threaded are now env-driven (`OPENEMS_HOST` default 127.0.0.1, `OPENEMS_THREADED` default on).** 127.0.0.1 is enough for **Tailscale Funnel** (Funnel proxies from localhost); set `OPENEMS_HOST=0.0.0.0` only for direct LAN/tailnet-IP access. `threaded=True` lets `/progress` poll during a run. To share with one remote tester: run the bridge, `tailscale funnel 8731`, give out `https://<machine>.<tailnet>.ts.net` — full walkthrough in `openEMS/WINDOWS_SETUP.md`.
- **openEMS is time‑domain**; frequency‑domain results come from an on‑the‑fly DFT. The "Field view" toggle is a visualization choice, not a different solver.
- **Reference numbering:** inline `[n]` must match the References `<ol>` position; the `.cref` link should point at the DOI directly. Confirm the count before assigning a new number.

## 9. Known limitations / honest caveats (state these, don't hide them)

- The flagship **MXene‑coated basswood is not yet hardware‑validated** — checked against textbooks + openEMS only. The **Measurement‑fit** tab (upload a VNA `.s2p`, extract effective σ, self‑calibrate) is the intended hardware validator.
- **S11 near cutoff** is a numerical waveguide‑port artifact, not a real reflection; a uniform matched guide is essentially reflectionless.
- **Interactive 3‑D field** = frequency‑domain steady |E|, normalized to its peak in **dB** (FDTD amplitudes are excitation‑relative).
- **Space‑survival** checks are first‑order screens (ECSS multipaction susceptibility; Stefan‑Boltzmann vacuum thermal), **not qualification**. MXene's secondary‑electron‑yield is essentially unmeasured — an open question.
- **Coating‑quality Phase 1** (roughness + uneven thickness) is exact textbook physics; **Phase 2** (porosity/seepage graded interface) is planned and will need a real sample to calibrate.
